# 機能仕様

4クライアント（Web / React Native / Flutter / KMP）が満たすべき仕様の正典です。
挙動に迷ったらこの文書が正となります。

表示する文言は原則としてサーバが返します（「毎日」「3日ごと」「前回: 50×10」など）。
クライアントに書き足さないでください。

## 全体の原則

1. **サインインなしで全機能が使える。** ログイン画面は起動導線から到達しない
2. **起動直後に「今日やるルーティン」が1タップで始められる。**
   サーバへの登録を待ってから画面を出さない
3. **ネットワークが無くても、起動・閲覧・記録ができる**
4. 破壊的な操作（削除・初期化）は必ず確認ダイアログを挟む

### 3の例外（移行で失ったもの）

**ルーティンの作成・編集にはオンラインが必要です。** 明確な機能後退です。

圏外で作れると、サーバの採番や検証を通っていないルーティンに対して記録が積まれ、
整合を取る手段が無くなるためです。保存ボタンを無効化し、理由を出してください。

> オフラインのため保存できません。電波のあるところで試してください。

記録（ワークアウト）は圏外でもできます。キューに積まれ、復帰時に送られます。

## 画面構成

```
タブ（4つ）
├── ホーム
├── ルーティン ──→ ルーティン作成 / 編集
├── 進捗
└── 設定 ──→ サインイン ──→ アカウント作成

ホーム or ルーティンから ──→ ワークアウト実行 ──→ サマリー
```

サインイン画面は**設定からのみ**到達します。

---

## ホーム

起動直後に表示される画面。

**表示物**

- 挨拶（時間帯で変わる: 5時前「おつかれさま」/ 12時前「おはよう！」/ 18時前「こんにちは！」/ それ以降「こんばんは！」）
- 今日の日付
- 連続記録バナー（現在の連続日数と最長記録）
- ルーティン一覧を3つに区分
  - **今日やる分** — 通常表示、タップでワークアウト開始
  - **今日は予定なし** — 薄く表示。タップすれば開始できる
  - **完了** — 薄く表示、「今日は完了しました」

**空状態**

- ルーティンが0件 → 「ルーティンがありません」＋作成ボタン
- 今日やる分も予定なしも0件（＝全部完了） → 「今日の分は完了です 🎉」

**更新タイミング**: 画面が前面に来たとき（ワークアウトから戻ったときに即反映させるため）

---

## ルーティン一覧

**各行の操作**

| 操作 | 動作 |
|---|---|
| 行をタップ | 編集画面を開く |
| ⏸ / ▶ | 停止・再開の切り替え。停止中はホームに出ない |
| 🗑 | 確認後に削除。**これまでの記録は残る** |
| 右下の ＋ | 作成画面を開く |

停止中の行は薄く表示し、「停止中」と添える。

---

## ルーティン作成 / 編集

作成と編集は同じフォームです。

**入力項目**

| 項目 | 内容 |
|---|---|
| 名前 | 必須 |
| アイコン | 絵文字10種から選択 |
| カラー | 8色から選択 |
| 頻度 | 毎日 / N日ごと / 曜日指定 |
| 種目 | 1つ以上必須 |

種目ごとに セット数・回数・重量kg・秒・休憩秒 を設定でき、↑↓で並べ替え、✕で削除できます。

**バリデーション**（3実装で文言まで一致）

| 条件 | メッセージ |
|---|---|
| 名前が空 | `ルーティン名を入力してください` |
| 種目が0件 | `種目を1つ以上追加してください` |
| 曜日指定で曜日未選択 | `曜日を1つ以上選んでください` |

エラー時は画面を閉じず、保存もしません。

**編集時の挙動**: 種目構成は丸ごと差し替わります。過去のセット記録は `exercise_id` で
紐づいているので消えません。編集画面からも削除できます。

**ピッカーの実装**: OSネイティブのPickerではなくボタン/チップで実装しています。
Webとネイティブで同じ操作手順にでき、E2Eが素直に書けるためです。

## ワークアウト実行

**ヘッダー**: 中断ボタン / ルーティン名と経過時間 / 完了ボタン
その下に進捗バー（完了セット数 ÷ 全セット数）。

**種目の切り替え**: 上部の横スクロールタブ、または下部の「前の種目」「次の種目」。
全セット完了した種目はタブに ✓ が付きます。

**セットの記録**

| 列 | 内容 |
|---|---|
| セット | 番号 |
| kg | 空欄なら自重 |
| 回 または 秒 | `target_duration_sec` があれば「秒」、なければ「回」 |
| 完了 | チェックボックス |

- セットを**完了にすると休憩タイマーが自動で始まる**（手動だと押し忘れるため）
- タイマーはタップでスキップできる
- 完了を取り消すとタイマーも止まる
- セットは「＋ セットを追加」「− セットを減らす」で増減。**最低1本は残す**

**前回の記録**: 前回のワークアウトの値が各セットの初期値に入り、種目名の下に
「前回: 50.0×10 / 50.0×10」のように表示されます。

**完了時のステータス判定**

| 完了セット数 | ステータス | サマリーの表示 |
|---|---|---|
| 全部 | `completed` | コンプリート！ |
| 1本以上 | `partial` | 記録しました |
| 0本 | `skipped` | 記録なし |

**中断**: 確認後、**何も保存せずに**戻ります。

---

## サマリー

完了直後に表示。時間・完了セット数・総重量・更新後の連続記録を出します。
総重量は kg×回 の合計で、自重種目は0として扱います。

「ホームに戻る」はスタックを戻ります（push で積み直すとタブが二重にマウントされるため）。

---

## 進捗

記録が0件のときは空状態を出します。

**表示物**

1. 集計 — 通算回数 / 今週の回数 / 連続日数 / 総時間
2. 実施状況グラフ — 7日 / 30日を切り替え可能な棒グラフ
3. カレンダー — 実施した日を塗る。◀▶ で前月・翌月へ移動でき、日をタップするとその日のワークアウト内容（ルーティン名・所要時間・種目ごとの整形済みセット）を開く
4. 種目ごとの推移 — 記録がある種目だけを選択でき、直近8回分の最大重量・総回数・総ボリューム

日別の内容は `day(date, timeZone)` が整形済みで返す（`setsLabel` は「50.0×10 / 50.0×8」形式。文言はサーバが決める）。

## 設定

**未サインイン時（匿名アカウント）**

> 📱 **この端末専用の記録です**
> サインインしなくても全機能が使えます。ただしアプリを削除すると記録も消えます。
>
> メールアドレスを登録すると、機種変更やアプリの入れ直しをしても記録を引き継げます。
> 今ある記録はそのまま残ります（作り直しは起きません）。

＋「バックアップを有効にする」ボタン（サインイン画面へ）

匿名でも記録はサーバに預けられていますが、
**取り戻す手段がこの端末にしか無い**という意味で「この端末専用」です。
「端末にしか保存していない」とは書かないでください。移行後は事実ではありません。

**サインイン時**

> ☁️ **バックアップ有効**
> （メールアドレス）
> 未送信の記録 N 件

＋「今すぐ送信」「サインアウト」

**共通**

- 保存されているデータの件数（ルーティン / 種目 / ワークアウト記録 / セット記録）
- バージョン
- **データを初期化** — 確認後、全削除して初期状態に戻す。**サーバ側も消える**

サインアウトの確認文言:
> サインアウトしても記録は消えません。この端末から見えなくなるだけで、
> 同じアカウントでサインインし直せば戻ります。

## サインイン / アカウント作成

**サインイン画面の冒頭に必ず出す文言**:
> サインインは任意です。しなくてもルーティンの作成も記録も全部使えます。
> 機種変更やアプリの入れ直しで記録を失いたくない場合だけ設定してください。

「あとで設定する」で閉じられます。

**バリデーション**

| 条件 | メッセージ |
|---|---|
| 未入力 | `メールアドレスとパスワードを入力してください` |
| 認証失敗 | `メールアドレスまたはパスワードが違います` |
| パスワード6文字未満（登録時） | `パスワードは6文字以上にしてください` |

アカウント作成後、メール確認が必要な設定なら「確認メールを送りました」を表示し、
それまでも記録を続けられる旨を添えます。

**メール登録では既存の記録が一切移動しません。**
匿名アカウントにメールとパスワードを足すだけで、`user.id` が変わらないためです。

## 判定ロジック

### 今日やるか（`isRoutineDueToday`）

| 頻度 | 判定 |
|---|---|
| 停止中 | 常に false |
| 毎日 | 常に true |
| 曜日指定 | 今日の曜日が `frequency_days` に含まれるか。**空なら毎日扱い** |
| N日ごと | 前回実施からN日以上経過。**未実施なら true**（今日から始められる） |

### 今日の分が済んだか

その日のログがあり、`status != skipped` なら完了扱い。

**全セット完了でなくても済んだ扱いにします。** 4種目中3種目やった日が未実施のまま
残ると、習慣化アプリとして逆効果だからです。

### 連続記録（ストリーク）

- `status != skipped` のログがある日を「やった日」として数える
- 最終実施日が**今日か昨日**ならストリークは継続中
- 2日以上空いたら0にリセット
- 最長記録は別に保持

「今日まだやっていない」だけで途切れた表示になると体験が悪いため、昨日までを許容します。
